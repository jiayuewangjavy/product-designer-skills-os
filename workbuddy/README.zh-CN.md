# WorkBuddy Workshop 版

此版本将上游 10 个能力合为 **一个可上传技能包**，Router 按需读取包内参考文件；不需要逐个安装技能，也不依赖 Codex 插件。原始 `skills/` 仍是唯一方法来源，`agents/openai.yaml` 继续服务 Codex。

## 学员安装（不需要终端）

1. 在 GitHub 打开 [product-designer-skills-os.zip](./product-designer-skills-os.zip)，点击 **Download raw / 下载原始文件**，保存 ZIP，不要解压。不要上传整个仓库的 Download ZIP。
2. 打开 WorkBuddy 桌面端，进入 **专家·技能·连接器 → 技能 → 添加技能 → 上传技能**，选择刚才下载的 ZIP。
3. 在“已安装”中确认 **产品设计 Skills OS** 存在并已启用，再开一个新对话。
4. 发送下方安装检查提示词。若没有命中，手动选择已安装的技能，再发送一次；不要只上传 ZIP 到普通聊天当作附件。

```text
请使用“产品设计 Skills OS”。先读取包内产品设计路由的参考指令，再处理：
我想做一个帮助自由设计师跟进客户反馈的小工具，目前只有想法，没有用户访谈。
请区分证据与假设，找出最高风险未知，选择最小验证闭环，并指出需要读取的能力文件。
不要编造访谈或直接生成完整产品。
```

预期：说明当前产品决策、最高风险未知、一个主能力（必要时补充支持能力）、退出条件与决策负责人；具体路线可不同，但应解释理由。只复述技能目录不算完成。

## 60 分钟 workshop

| 时间 | 活动 | 学员产出 |
|---|---|---|
| 0–10 分钟 | 安装、启用、运行检查提示词 | 可使用技能；区分方法与工具权限 |
| 10–20 分钟 | 用案例或自己的产品运行 Router | 最高风险未知、最小闭环、停止条件 |
| 20–35 分钟 | 明确验证问题；有必要时做最小原型 | 可检验问题或最小交互，标明模拟内容 |
| 35–50 分钟 | 两人互测，记录实际观察 | 行为记录、原话、阻塞点；不虚构测试 |
| 50–60 分钟 | 复盘并再次路由 | 保留 / 修改 / 否决 / 延后的决策与下一个未知 |

### 练习一：把想法变成可验证问题

```text
使用“产品设计 Skills OS”。练习背景：自由设计师在微信、邮件和会议中收到客户反馈，
担心遗漏修改项。我只是根据个人经历提出这个想法，尚未做外部研究。
请建立精简产品上下文，再用 Router 判断最值得验证的未知。
选择一个主能力并实际执行，给出最小验证行动、证据记录方式和停止条件。
用中文输出，明确标注所有未验证假设。
```

### 练习二：按明确任务直接执行

```text
使用“产品设计 Skills OS”的原型问题和交互原型能力。
这次只验证：参与者能否在不经讲解的情况下，把三条模拟客户反馈转成可追踪修改项。
请制作单文件 HTML 原型，包含待整理、已确认、待澄清状态，以及可重置的模拟数据。
不要接入微信、真实客户数据或后端。给出操作方法和观察记录表。
如果当前环境不能运行代码，请给出可保存文件并明确说明尚未运行验证。
```

这条提示词显式指定任务，用于练习跳过重新路由；它不代表练习一已证明该方向正确。

### 练习三：用真实观察更新决策

```text
使用“产品设计 Skills OS”的学习闭环复盘能力。
下面是本次互测的真实记录：[粘贴观察；没人测试时写“尚未测试”]。
请区分观察与解释，指出哪些假设有支持、哪些仍未知。
写出要保留、修改、否决或延后的决策，以及下一步最小验证。
没有足够观察时只给验证计划，不虚构结论。
```

## 讲师验收与限制

仓库脚本验证的是格式、资源完整性和生成一致性，**尚未代表 WorkBuddy 客户端实测通过**。讲师在自己的客户端至少完成以下流程后，才可把对应版本标记为“实测通过”：

- 导入 ZIP 成功，名称正确，技能可启用。
- 新会话中运行安装检查，确认读到 Router 的实际指令。
- 明确指定原型问题，确认直接执行且能读取补充资料。
- 能生成并打开原型；无法执行时如实说明。
- 无测试记录时不编造研究、观察或有效性结论。
- 换会话后粘贴已保存上下文，能够接着复盘。

记录客户端版本、操作系统、包版本、测试日期、通过项与失败现象。联网研究、Figma 编辑或线上发布仍取决于当前客户端的工具和授权；技能包不会自动增加这些能力。

## 常见问题

- **上传解析失败**：确认上传的是本目录单技能 ZIP，解压后应是 `product-designer-skills-os/SKILL.md` 和 `references/`，没有额外仓库层级。
- **只报技能名，不执行**：明确要求读取包内对应 `references/<能力名>.md` 并完成任务；若客户端无法读取附属文件，记录错误，不把这一结果记为通过。
- **回复英文**：提示“按中文执行”；原始方法参考以英文保留，入口已声明跟随用户语言。
- **打不开 GitHub**：讲师可提前下载并分发相同 ZIP，同时保留随包的 MIT 许可和上游归属；学员运行技能不需要连接 GitHub。
- **找不到 Codex 插件**：本包不依赖 Codex 插件。所需外部服务应在 WorkBuddy 配置可用连接器，或改用用户提供的附件。

## 维护与重新打包

从仓库根目录执行（Python 3，无第三方依赖）：

```bash
python scripts/validate_skills.py
python scripts/build_workbuddy.py
python scripts/build_workbuddy.py --check
```

修改原始 `skills/` 后重新生成；不要手动编辑生成目录。ZIP 与展开目录提交到同一版本，GitHub 下载即可使用。

官方依据（2026-10-28 核对）：[技能包结构与字段](https://open.workbuddy.cn/docs/skill)、[WorkBuddy 上传与启用技能](https://www.workbuddy.cn/docs/workbuddy/From-Beginner-to-Expert-Guide/Function-Description/Skills-Market)。本仓库适配包由上游维护者提供，不表示腾讯官方认证或市场上架。
